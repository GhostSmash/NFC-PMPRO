# NFC PM-Pro (web) — рабочие заметки для ИИ-ассистента

Веб-программатор для считывателя **300CD Pro** (USB HID, VID `0x1629` PID `0x1831`, usage page `0xFF00`).
Работает в Chrome/Edge через **WebHID** — без драйверов и установки. Исходный C#-проект (WinForms) см. в `nfcpm.zip`: `Furui.cs` (протокол), `PmPro.cs` (команды), `App.cs` (логика UI) — это эталон поведения.

## Запуск
- Открыть `index.html` в Chrome/Edge (file:// работает) или `python -m http.server` → `http://localhost:8000`.
- Закрыть `NFC_Pro.exe` и любые программы, держащие устройство. Первое подключение — кнопка «Выбрать устройство» (нужен жест пользователя).
- Только классические `<script>` (НЕ ES-модули): модули не грузятся с file://. Порядок подключения в `index.html` важен — все функции глобальные.

## Протокол (кратко)
- Кадр: `[len_lo,len_hi][payload…][crc_lo,crc_hi]`, `len = payload+4`, дополняется нулями до кратного 64 байтам, **весь буфер шифруется RC4** (ключ из 12 байт `KEY` в `protocol.js`, состояние сбрасывается на каждый кадр). CRC считается по `len+payload` до шифрования.
- Отправка: `device.sendReport(0, 64 байта)`. Приём: событие `inputreport` (64 байта), кадр может занимать несколько отчётов.
- Ответ: `d[2]==1` — ACK. Полезные данные в `d.slice(2, n-2)`.
- Хендшейк: `06` → `01 01 00 14 0F 04 90 14 00 00` → `01 + d[12..15]` → `06`.
- Команды: `09 01 02` писк · `10` активация HF · `21` чтение HF (UID/ATQA) · `17`/`18`/`16` чтение/запись/формат сектора (15 байт заголовка: код, сектор, флаг авторизации 1=A/2=B/3=A+B, KeyA(6), KeyB(6)) · `13` подбор ключей (тип 1=A, 2=B) · `1D 00` magic gen1a · `28 01 00` чтение LF · `2D freq id4 plant` запись LF · `29` чтение HID · `2E id12` запись HID.
- Все команды идут через очередь `exec` (одна за раз). Не обходить её.

## Известные проблемы / что доработать (по приоритету)
1. **Запись 125 кГц не получает ответ от устройства** (чтение работает). В `lf-hid.js` запись теперь ждёт до 10 с и пишет в журнал `LF write: ack= ms= raw=`. Нужно по этому логу разобраться: приходит ли вообще ответ, какие байты, не требуется ли предварительная команда/пауза, не отличается ли код ответа. Сверять с `PmPro.WriteLf` и `App.WriteLfAsync` в C#. В консоли (вкладка «Консоль») можно слать сырые команды, например `2D 00 41 EE 00 51 37`.
2. **Кнопки**: форма hover/active исправлена в конце `style.css` (оверлей через `::after` вместо inset-тени 99px, контур `.out` не пропадает, единый focus-ring). Если на железе/экране всё ещё «кривятся» — смотреть скриншот. Раньше: **кнопки визуально «кривились»** (скругления/клип-путь искажаются при нажатии/наведении), у части кнопок **пропали анимации нажатия**. Смотреть `css/style.css`: `.btn`, `transition`, `border-radius`, `clip-path`, `:active`, и `data-sh`/`shp()` в `core.js`.
3. Раскладка в оконном (не полноэкранном) режиме: журнал уезжал за нижний край. Добавлен блок «layout fixes» в конце `style.css` — проверить на разных высотах окна.
4. Не проверено на железе: запись секторов MIFARE, форматирование, magic-тест, подбор Key B. После изменений в протоколе всегда проверять хендшейк (в Обзоре должен показываться реальный серийный номер).

## Правила работы
- Не менять формат кадра/ключ RC4/хендшейк без проверки на устройстве.
- Перед записью на метку — всегда `confirmBox`; после записи — проверка чтением (как в C#).
- Новые функции протокола — в `protocol.js`, UI-логика — в файле своей вкладки.
- Каждый файл проверять `node --check js/<файл>.js` перед отдачей.
- Тексты интерфейса — на русском.
